# Memórias do agente Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** O Cockpit guarda memórias curtas por escopo, injeta as que valem para a sessão dentro de um teto, deixa o agente gravar e buscar pela CLI, e oferece uma página para triar, editar e importar dos `napkin.md`.

**Architecture:** Um pacote puro `internal/memory` (normalização, semelhança, parser do napkin, seleção com teto, formatação do bloco). A store guarda a tabela `memories` (migração 015) e cria candidatas a partir das decisões de card concluído. A API expõe `/api/me/remember`, `/api/me/memories` (para a CLI) e `/api/memories/*` (para a página). O SessionStart do adaptador Claude acrescenta o bloco. A página "Memórias" fica no menu.

**Tech Stack:** Go (net/http, SQLite), React + TypeScript + TanStack Query + Vitest.

**Spec:** docs/superpowers/specs/2026-11-19-memorias-design.md

## Global Constraints

- Categorias: `execucao`, `shell`, `dominio`, `diretiva` (rótulos: "Execução e validação", "Shell e comandos", "Regras do domínio", "Diretivas do usuário").
- Status: `ativa`, `candidata`, `arquivada`, `descartada`. Origem: `agente`, `usuario`, `napkin`, `card`.
- Escopo: `project_id` NULL = global; senão o projeto (raiz, solto ou app).
- Sessão recebe: globais + as da raiz da família do projeto efetivo + as do projeto efetivo (se for app). Projeto efetivo = projeto do card da sessão, senão o da sessão.
- Regra ≤ 300 caracteres, ação ≤ 400; quebras de linha viram espaço; regra vazia recusada (CLI/API); na importação, texto maior é cortado com "…" e marcado `needs_review`.
- Normalização: minúsculas, sem acento, sem pontuação, espaços simples. Duplicada = regra normalizada igual; parecida = Jaccard de palavras normalizadas ≥ 0,6. Compara só a regra.
- Deduplicação de criação (importação e card): regra normalizada igual no mesmo escopo, contra qualquer status (inclusive `descartada`) → não cria.
- Teto padrão 1500 tokens (bytes/4), setting `memory_budget_tokens` entre 0 e 6000 (0 desliga). Ordem: app → raiz → global; dentro do escopo, `position` asc e depois id asc; memória que não cabe é pulada; cabeçalho e linha "+N" fora do teto.
- Bloco injetado:
  ```
  Memórias deste projeto (do Cockpit; use nobre lembrar para gravar e nobre memorias <termo> para buscar; não leia nem edite .claude/napkin.md):
  - [shell] <regra> → <ação>
  +N memórias fora do limite: nobre memorias <termo>
  ```
  (a linha "+N" só quando N > 0; sem nenhuma memória ativa o bloco não aparece.)
- Decisões automáticas do Cockpit (`Why == "detectado pelo Cockpit"`, internal/board/integration.go) não viram candidatas.
- Textos em português, curtos. Migração `internal/store/migrations/015_memories.sql`.

## Review Focus

- Sessão com card num app: a injeção usa o app do card, não o projeto da sessão (Task 4 `TestSessionStart_MemoriesFollowCardApp`).
- Teto: memória enorme no topo não impede as menores; "+N" correto (Task 1 `TestSelect_SkipsLargeKeepsSmall`).
- Reimportar o mesmo `napkin.md` e reabrir/concluir o mesmo card não duplicam nem ressuscitam descartadas (Task 2 e Task 3).
- `napkin.md` gigante e irregular (239 KB, itens sem data, "Do instead" em várias linhas, seções fora do padrão) importa sem erro (Task 1 `TestParseNapkin_Irregular`, com fixture realista).
- Sessão sem captura completa não recebe memórias, e `memory_budget_tokens = 0` desliga (Task 4).

  ```go
  type Memory struct {
      ID          int64     `json:"id"`
      ProjectID   *int64    `json:"project_id"` // nil = global
      Category    string    `json:"category"`
      Rule        string    `json:"rule"`
      Do          string    `json:"do"`

  // store
  func (s *Store) CreateMemory(m domain.Memory) (domain.Memory, error)            // valida/limpa; Position = fim do escopo/categoria
  func (s *Store) UpdateMemory(m domain.Memory) (domain.Memory, error)            // regra, ação, categoria, escopo, status, needs_review

      Status     string  // "" = todos menos descartada
      Term       string  // busca em regra/ação (normalizada)
  }
  func (s *Store) MemoryExists(projectID *int64, rule string) (bool, error)        // regra normalizada, qualquer status
  func (s *Store) CardMemoryCandidates(cardID int64) (int, error)                  // decisões do card → candidatas; devolve quantas criou

  ```
  Migração:
  ```sql
  CREATE TABLE memories (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    workspace_id TEXT NOT NULL DEFAULT 'local',
    owner_id TEXT NOT NULL DEFAULT 'me',
    project_id INTEGER REFERENCES projects(id) ON DELETE CASCADE,
    category TEXT NOT NULL CHECK (category IN ('execucao','shell','dominio','diretiva')),
    rule TEXT NOT NULL,
    rule_norm TEXT NOT NULL,
    do_text TEXT NOT NULL DEFAULT '',
    status TEXT NOT NULL CHECK (status IN ('ativa','candidata','arquivada','descartada')),
    source TEXT NOT NULL CHECK (source IN ('agente','usuario','napkin','card')),
    source_ref TEXT NOT NULL DEFAULT '',
    position INTEGER NOT NULL DEFAULT 0,
    needs_review INTEGER NOT NULL DEFAULT 0,
    created_at TEXT NOT NULL,
    updated_at TEXT NOT NULL
  );
  CREATE INDEX idx_memories_scope ON memories(project_id, status);
  CREATE INDEX idx_memories_norm ON memories(rule_norm);
  ```
  (Confira como as migrações existentes lidam com FK para `projects` e o marcador `-- nobre:foreign_keys=off` da 011; uma futura reconstrução de `projects` precisa considerar esta FK.)
